# 다국어 (i18n)

manage-modules는 **행-당-언어(row-per-language)** 방식의 다국어를 기본 지원합니다. 하나의 콘텐츠를 언어별로 별도 행으로 저장하고, 목록·작성·순서 변경이 모두 현재 선택된 언어를 기준으로 동작합니다.

## 설계 개요

- **번역 = 별도 행**: 같은 공지의 한국어판과 영어판은 `lang` 값만 다른 두 개의 행입니다. (번역을 JSON 컬럼에 몰아넣지 않음 → 검색·정렬·페이지네이션이 단순)
- **단일 진실 공급원**: 지원 언어 목록은 `APP_CONFIG.LANG` 한 곳에서 관리합니다.
- **서버 필터**: 목록 조회 시 서버 액션이 `lang` 조건을 강제하므로 클라이언트가 언어를 임의로 섞을 수 없습니다.

```typescript
// src/app.config.ts
LANG: {
  CODES: ['ko', 'en', 'ja'] as const,
  LABELS: { ko: '한국어', en: '영어', ja: '일본어' },
  DEFAULT: 'ko',
},

export type LangCode = (typeof APP_CONFIG.LANG.CODES)[number];
```

## 구성 요소

| 위치 | 역할 |
| --- | --- |
| `app.config.ts` `APP_CONFIG.LANG` | 지원 언어 코드·라벨·기본값 (SSOT) |
| DB `lang TEXT NOT NULL DEFAULT 'ko'` | 각 행의 언어 |
| `_base/actions/get-list.ts` | `useLangFilter` 시 `.eq('lang', ?)` 적용 |
| `_base/ui/manage-header.tsx` | 언어 전환 버튼(`CategoryButtonGroup`, `paramKey="lang"`) |
| `{module}/list-columns.tsx` | 언어 뱃지(`APP_CONFIG.LANG.LABELS[lang]`) |
| `{module}/write-form.tsx` | 새 행에 현재 언어 주입 |

## 동작 흐름

1. **언어 전환** — 헤더의 언어 버튼이 URL 쿼리 `?lang=en`을 설정합니다. `showAllOption={false}`라 항상 정확히 한 언어가 선택됩니다(기본값 `APP_CONFIG.LANG.DEFAULT`).

   ```typescript
   // _base/ui/manage-header.tsx
   <CategoryButtonGroup
     options={langOptions}          // APP_CONFIG.LANG.CODES 기반
     paramKey="lang"
     showAllOption={false}
     defaultValue={APP_CONFIG.LANG.DEFAULT}
   />
   ```

2. **목록 필터(서버)** — `get-list`가 현재 언어로 조회합니다.

   ```typescript
   // _base/actions/get-list.ts (요약)
   if (useLangFilter) {
     query = query.eq('lang', lang || APP_CONFIG.LANG.DEFAULT);
   }
   ```

3. **작성** — 새 행은 현재 선택된 언어로 생성되고, 수정 시에는 기존 언어를 유지합니다.

   ```typescript
   // {module}/write-form.tsx
   const currentLang = searchParams.get('lang') || APP_CONFIG.LANG.DEFAULT;
   // 폼 기본값
   lang: prevValues?.lang ?? currentLang,
   ```

4. **순서 변경** — `swap-order`도 같은 언어 안에서만 순서를 바꿉니다(`.eq('lang', filters.lang)`).

## 새 모듈에 다국어 적용

**1. DB 마이그레이션** — `lang` 컬럼과 복합 인덱스 추가

```sql
lang TEXT NOT NULL DEFAULT 'ko',

-- 목록 쿼리(deleted, lang [, sort_order/created_at])에 맞춘 복합 인덱스
CREATE INDEX idx_[table]_deleted_lang_created
  ON public.[table](deleted, lang, created_at DESC);
```

**2. config.ts** — `useLangFilter`는 기본 `true`이므로 별도 설정 불필요. `lang` 컬럼이 **없는** 테이블만 명시적으로 꺼야 합니다.

```typescript
// lang 컬럼이 없는 모듈 (예: inquiries, admins)
export const CONFIG = {
  tableName: 'inquiries',
  useLangFilter: false, // 필수 — 없으면 존재하지 않는 lang 컬럼으로 쿼리해 오류
} as const;
```

**3. 페이지 헤더** — 언어 필터를 숨기려면 `showLangFilter={false}`

```typescript
<ManageContainer title={CONFIG.title} moduleName={CONFIG.moduleName} showLangFilter={false}>
```

**4. list-columns.tsx** — 언어 뱃지(선택)

```typescript
import { APP_CONFIG, type LangCode } from '@/app.config';

{
  accessorKey: 'lang',
  cell: ({ row }) => {
    const lang = row.original.lang as LangCode;
    return <Badge variant="outline">{APP_CONFIG.LANG.LABELS[lang] ?? lang}</Badge>;
  },
}
```

## 시드 데이터

`supabase/seed.sql`에는 기본 언어(`ko`) 데이터와 함께 일부 `en` 행이 포함되어 있어, 언어 전환 UI를 바로 확인할 수 있습니다. 언어를 추가하려면 `APP_CONFIG.LANG.CODES`에 코드를 넣고 해당 언어의 행을 시드하면 됩니다.

## 주의사항

- `useLangFilter`의 기본값은 **true**입니다. `lang` 컬럼이 없는 테이블에서 끄지 않으면 조회가 실패합니다.
- 언어 필터는 "전체" 옵션이 없습니다(`showAllOption={false}`). 목록은 언제나 단일 언어를 보여줍니다.
- 이 다국어는 **콘텐츠 데이터**를 위한 것입니다. 관리자 UI 자체의 문자열(버튼 라벨 등)은 별도 i18n 프레임워크 대상이 아닙니다.
